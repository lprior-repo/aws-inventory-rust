# Review of 2026-11-18, and what changed

> Status: Record. An outside review of the plan archive of 2026-11-15 and
> 2026-11-16 was supplied by the owner on 2026-11-18. Each finding was checked
> against the plan's text (not against running code) and applied. The review
> itself says its findings are about the proposed plan and were not reproduced
> against the repository.

## Findings

| # | Finding | Did the plan say that | Fix | Where |
| --- | --- | --- | --- | --- |
| 1 | Crash recovery is proven only for a killed collector. Asynchronous commit and an unlogged table for deletion evidence could lose observations in a database crash, or leave the graph ahead of SQL | Yes. B4.3 killed the collector only; B4.4 measured `synchronous_commit = off` as a candidate default; B4.5 made `scope_seen` unlogged and detected a crash only at the collector's next start | Durable defaults stay. A new test kills the database with the collector running. `scope_seen` is logged by default, and a server restart is detected inside scope completion. The graph is repaired when the store recovers behind it | B4.3, B4.4, B4.5, new B4.6, new E4.3 |
| 2 | The UI uses one database URL for the writable store and the SQL console | Yes. D2.1 opened the store "on the same URL the reader uses" | Two roles and two URLs, provisioned before the console. | 3 | Inserting parent links only when absent keeps a stale parent after a resource moves | Yes. B4.5 item 4 | Parent sets are reconciled per child in the page's transaction: insert new, delete unobserved, write nothing when equal. A reparenting test is added | B4.5 |
| 4 | A list that only creates describe work leaves no durable membership, so a vanished ID may never be removed | Yes. A3.4's work-only plan stored no observation and passed no scope parent | A logged `scope_members` table written with the page and reconciled at completion; tests for disappearance, denied describes, interrupted and reordered pages | A3.4 |
| 5 | Excluding fields from the hash to make the warm sweep pass can hide real state | Yes. A7.3 told the worker to exclude whatever member changed | Order differences are normalized instead. An exclusion needs a reason from a closed list and is refused for identity, name, relation, tag, state or configuration members. Tests prove real changes still reach SQL and the graph | A7.3 |
| 6 | A partial batch response is not proof of absence, and similar shapes do not justify skipping a describe | Partly. B6.3 did not classify per-ID outcomes; B6.2 compiled an overlay `skip` key without saying how equivalence is established | Five outcomes per requested ID; only authoritative not-found counts toward deletion. A skip needs a recorded member-by-member comparison from the probe | B6.2, B6.3 |
| 7 | Inferred edges need a namespace and a way to be withdrawn | Partly. E1.2 counted ambiguity within a sweep but had no account or region scope and no retraction | ARNs match globally; bare IDs only within the account and, for regional kinds, the region. Affected sources are recomputed when identities appear, vanish or change, and an edge is withdrawn when its match stops being unique | E1.2 |
| 8 | "Digest last" is not a migration protocol; names must be stable; budgets should be in bytes | Yes. C1.6 ordered the digest last and resumed "on the next upgrade" with no journal | A persisted field-ID-to-column mapping, a migration journal, an advisory lock, resumable cursors, one-transaction activation, additive-only DDL, and byte bounds for rows and in-flight data | C1.2, C1.6, new C1.7 |

## Order

The review's order: pin the revision and baseline; get the small EC2 case onto
PostgreSQL; establish durability, security and benchmark harnesses; add one
child case and graph reconciliation; then widen and optimize; treat the full
emulator sweep and the UI scale target as later gates.

The plan already had most of this shape: the gate fix and baseline in wave 0,
the existing scenario on PostgreSQL before anything else is deleted, the
benchmark before the speed work, the thin slice before all 436 services, and
the full sweep and frame target only in waves 5 and 6. What moved:

- B4.6 (database crash) and C4.1 with D13.1 (roles) now come before any
  relaxed write setting and before the console.
- E4.3 (graph repair) joins the graph-equals-SQL work.
- Pinning the repository revision: the plan was written from an archive with
  no git history. Step A0.1 now starts by recording the commit it runs on.
