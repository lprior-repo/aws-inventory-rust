# Thin-slice comparison status — 2026-11-24

B9.2 is **not complete**. No CloudQuery or Steampipe comparison has been
recorded. Their published-release versions, AWS plugin licensing/free-use
availability, and custom-endpoint/private-CA support remain unverified. No
competitor binaries or images have been added to the repository, and no

## Evidence scope

The native self-comparison scenario runs this collector under `ours` and
`ours2`, three times each, with **S3 only**. It requires exact full observed
count maps between both names and all runs, exactly the seeded bucket count,
the common kind `AWS::S3::Bucket`, and the six-sample rotation. The recorded
attempt below failed and does not establish successful self-comparison or
B9.2 evidence against CloudQuery and Steampipe.

The EC2+S3 scenario is a **known-failure assertion**, not successful equal-count
or done-when evidence. `DescribeTrunkInterfaceAssociations` returns
`Fatal (OperationNotPermitted)` and the collector exits 2. Both names must be
reported failed, with the failed operation in stderr and no timing. No
operation is excluded and exit 2 is not accepted as success. If the emulator or
collector resolves that failure, the known-failure assertion must be revisited.

The round-3 S3 validation attempt returned five matching observations of two
buckets; the sixth sample failed with `canceling statement due to statement
timeout at line 3444`. The coordinator confirmed from the PostgreSQL server log
that `DROP DATABASE ... WITH (FORCE)` waited for a forced checkpoint beyond the
shared helper's ten-second statement limit under other lanes' load.
`comparison_ready` correctly remained false. This attempt is not a successful
comparison; the coordinator owns the separate DDL-timeout fix and the native
rerun after that fix lands.

## Reproduction

With the PostgreSQL administrative URL, installed emulator/FalkorDB runtimes,
and built collector configured as described in the adjacent README:

```sh
cargo test -p inventory-harness --test head_to_head_native \
  given_our_collector_under_two_names_when_compared_then_counts_are_equal -- --ignored
cargo test -p inventory-harness --test head_to_head_native \
  given_known_ec2_failure_when_compared_then_both_names_fail_without_timing_and_name_scope -- --ignored
```

These tests invoke the real harness CLI and inspect its generated report; their
scratch reports are not a retained competitor benchmark. Completing B9.2 still
requires installing the published competitor releases outside the repository,
verifying their endpoint/CA and licensing behavior, writing executable tool
definitions, and retaining a real report with versions, dataset, machine and
common kinds. The emulator has neither account quotas nor real-network latency;
any future comparison measures local engines, not real-account quota handling.
